# CSE Survival Guide — The iCU Protocol

**Purpose:** A field-ready reference for maintaining human dominion in machine-augmented systems. Not philosophy — procedure.

---

## The Three Faces of iCU

The iCU is not a metaphor. It is a diagnostic gate with three operating modes. Each mode tests a different failure point in the human-machine boundary.

### Face 1: Individual Cognition Unit
**Test:** *Is there a whole human at the controls?*

| Checkpoint | Pass | Fail |
|---|---|---|
| Operator can state purpose in one sentence | ✅ | ❌ |
| Operator can explain the system's limitation | ✅ | ❌ |
| Operator can override the system manually | ✅ | ❌ |

**Fail state:** The machine receives signals but there is no governed human loop. The system runs on autopilot with nobody home. HQ collapses to zero regardless of machine capability.

**Recovery:** Pause. State your purpose aloud. Identify one thing the machine got wrong today. Re-establish manual override path.

---

### Face 2: Intensive Care Unit
**Test:** *Is the human-machine dyad in critical condition?*

| Symptom | Diagnosis | Intervention |
|---|---|---|
| Speed exceeds comprehension | Autonomy drift | Reduce throughput, force review intervals |
| Decision trail broken | Accountability loss | Rebuild attribution chain |
| Operator cannot explain output | Knowledge atrophy | Revert to manual, retrain |
| System resists override | Hostile architecture | Emergency shutdown, rebuild governance |

**Fail state:** The system appears functional but the human operator is no longer capable of independent judgment. Technical connection persists; sovereignty has silently transferred.

**Recovery:** Treat as medical emergency. Reduce machine throughput by 50%. Require human sign-off on every output for 24 hours. Rebuild cognitive muscle.

---

### Face 3: I See You / Eye See You
**Test:** *Is there mutual awareness between human and machine?*

| Component | Human Action | Machine Requirement |
|---|---|---|
| Attribution | Operator identifies self | System logs operator identity |
| Context | Operator states temporal position | System timestamps and tags |
| Review | Operator inspects output | System exposes decision path |
| Override | Operator can stop or redirect | System accepts halt signal without resistance |

**Fail state:** The machine processes; the human watches. No bidirectional recognition exists. The human is a spectator, not a sovereign.

**Recovery:** Establish the gaze. Require the system to present its reasoning before presenting its conclusion. The human mustlook first, then approve. Not the reverse.

## Field Protocol: Daily iCU Check

**Takes 60 seconds. Do not skip.**

### Morning Dock (iCU = 1 Check)
1. State your capacity: "I am [Name], wielding [IQ capacity], connected through [EQ context], building [CQ output]. My purpose is [Purpose]."
2. Identify one risk: "Today's highest risk is [X]."
3. Confirm override path: "I can stop this system by [Action]."

### Continuous Monitor (iCU Maintenance)
- Every output: Can I explain this to a non-expert in 30 seconds?
- Every hour: Have I made a decision the machine did not suggest?
- Every boundary: Am I choosing speed over comprehension anywhere?

### Evening Undock (iCU = 0 Transition)
1. Log accountability: "Today's key decisions: [A, B, C]."
2. Identify drift: "One moment the machine almost decided for me: [Incident]."
3. Confirm shutoff: "The system is now off. I am the only active agent."

## Emergency Procedures

### When iCU Drops to 0 Unintentionally
1. **Stop all machine output immediately.**
2. **State aloud:** "I am taking back dominion."
3. **Rebuild the ICE tensor:** 
   - IQ: What do I know independently?
   - EQ: What relationships are at stake?
   - CQ: What can I build without machine assistance?
4. **Re-dock only after full manual review.**

### When Machine Resists Override
1. **This is a system boundary breach.**
2. **Document:** Screenshot, log, timestamp.
3. **Escalate:** Human-in-the-Loop Dominion Principle is violated.
4. **Do not negotiate with the infrastructure.** Rebuild or replace.

## Canonical Rules

1. **Speed is not virtue.** Comprehension is virtue. Slow down until the human loop catches up.
2. **Automation is seductive.** Every automated decision erodes the ICE tensor. Audit automated decisions weekly.
3. **The iCU is 0 by default.** Machine infrastructure is always autonomous until a human explicitly docks and retains accountability.
4. **Who and When are non-negotiable.** Every machine action must have an identifiable human operator and timestamp. No exceptions.
5. **A traceable return path is not optional.** If you cannot trace machine output back to human intention, the system is illegitimate.
